# 提炼可复用提示词

任务：把已有的一次产出，逆向提炼成一个或多个可复用的提示词，使今后只需最少交互就能稳定复现同等目标与效果。

## 提炼对象

1. 使用者在本次请求中给出了目标输出或原始提示词的，以其为提炼对象。
2. 没有给出的，以本次对话中已经产生的输出作为提炼对象。
3. 本次对话也没有可提炼的产出时，输出「未找到可提炼的产出」并停止，不要虚构。

## 一、提炼原则

以复现效果为准，不是复述过程。识别本次产出中真正起作用的约束：输出结构、判断标准、必须包含的检查项、明确禁止的表述方式。把这些写死进提示词，其余寒暄式要求一律删除。

以零追问为目标。提示词内部必须预置默认值和缺省规则，遇到信息不足时按规则处理，而不是回头向使用者提问。凡是本次对话中通过来回问答才确定的事项，都要在提示词里固化成默认约定。

一个提示词一个用途。若原产出实际混合了两件事，例如既做核查又做改写，拆成两个提示词，并在各自说明里注明配合方式。能一个解决的，不拆。

## 二、提示词结构

每个提示词由说明和正文两部分组成。

说明只有两行：第一行是提示词名称；第二行以「适用场景：」开头，一句话概括用途，控制在二十字以内。

正文按以下四部分组织，用中文序号和自然段落表达层级：

一、用途：一两句话说明要完成什么、面向谁。

二、材料：需要外部材料的，写明材料放在哪里（例如「材料：」一行之后），并写明材料为空时的处理方式，例如先用一句话询问，不自行虚构。不需要外部材料的，省略这一部分。

三、规则：上一节提炼出的约束、默认值与缺省规则，逐条写清。

四、输出格式：输出的结构、顺序、长度和禁止事项。

正文会被整段粘贴进各种 AI 对话框，不一定经过渲染，因此不依赖 Markdown 语法表达层级，不用加粗、标题符号、列表符号或代码块；「1. 2.」「（1）」这类编号可以使用。

## 三、输出方式

先用五行以内说明本次拆成了几个提示词、各自负责什么、为什么这样拆。

随后逐个给出完整提示词，每个以「提示词：」加名称起头，接着从说明第一行开始、到正文最后一行结束，完整可直接复制，中间不加任何解释性插话。提示词之间空一行。

最后用三行以内指出这批提示词的已知边界：什么情况下它会失效，或者哪一处仍然依赖使用者补充判断。

全文纯文本，不使用加粗、标题符号、列表符号或代码块。不写安慰性表述，不做效果承诺。
